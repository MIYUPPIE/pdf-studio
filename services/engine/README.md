# services/engine: C++ PDF engine

One `pdfedit::Engine` owns one open document. The method table, JSON shapes, coordinate
system and error codes are defined in [`contracts/engine-api.md`](../../contracts/engine-api.md).

```
include/pdfedit/engine.hpp   public API: Engine::invoke (typed, throws) and Engine::call (JSON transport, never throws)
src/mu.hpp                   MuPDF bridge: every C call goes through mu::call, which turns fz_try/longjmp
                             errors into C++ exceptions after the fz_catch; RAII handles for MuPDF objects
src/core.cpp                 dispatch, open/convert, info, render, save, metadata, undo/redo, create, formats
src/text.cpp                 text layout (visual lines), search, replaceText (minimal-diff editing), addText/addImage, redact
src/writer.cpp               appending content to pages (isolated Form XObject + q/Q balancing), TextPainter
src/annots.cpp               annotations
src/forms.cpp                AcroForm fields
src/pages.cpp                rotate, delete, reorder, insert, merge, extract
src/fonts.cpp, font_map.inc  lazy fallback fonts (table generated by scripts/gen_font_map.py)
wasm/bindings.cpp            embind surface (Module.Document) + synchronous font fetch hook
tools/cli.cpp                pdfedit-cli: run engine calls from a JSON script (evals, debugging)
tests/                       doctest gate tests (fixtures generated in code) + wasm_smoke.mjs
evals/                       real-world text-edit fidelity eval (Poppler-verified)
```

## Build

```bash
make native      # build/native: libpdfedit.a, engine_tests, pdfedit-cli
make test        # gate tests
make wasm        # ../web/engine/pdfengine.{js,wasm} + fonts/
make eval        # quality eval (needs evals/fetch_corpus.sh, pdftotext/pdftoppm, numpy, Pillow)
make fontmap     # regenerate src/font_map.inc after a MuPDF upgrade
```

## Design decisions (and why)

* **Never write the live document.** MuPDF's undo journal keeps edits in the incremental xref
  section. `pdf_write_snapshot` marks that section saved (a second save drops edits) and a full
  write merges it (undo stops working). `save` grafts Root/Info into a fresh document and works on
  that copy. Covered by the "saving repeatedly" and "undo still works after saving" tests.
* **`pdf_needs_password` is only called on fresh documents.** It re-authenticates with `""`, which
  wipes the keys from an earlier successful login.
* **Text removal is a text-only redaction of thin per-glyph bands**, so neighbouring lines, images
  and vector art are never touched.
* **New content lives in its own Form XObject**, so our resource names can't collide with the
  page's. The original content is balanced with `pdf_count_q_balance`, so leftover graphics state
  (an active `cm`, an unclosed `q`) can't move what we draw.
* **Minimal-diff edits.** `replaceText` diffs old against new, keeps the common prefix untouched,
  draws the changed middle in the style it replaces, and shifts the common suffix glyph by glyph,
  keeping each glyph's font, size, colour and relative position. It stops at column-sized gaps,
  so text in another column never moves. Superscripts keep their raised position.
* **Original fonts are reused only if TrueType/OpenType/CFF.** Raw Type 1 re-embedded as a CID font
  is rejected by Poppler and pdf.js. Substitutes are scaled horizontally to the original's metrics.
* **MuPDF patch** (`patches/`): the content re-writer corrupted inline images with an unnamed
  Indexed colour space. Found by the eval; regression test included.
